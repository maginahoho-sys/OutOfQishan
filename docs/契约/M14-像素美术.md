# M14 像素美术（Pixel Art）

> 目标：把项目里用 Phaser `Graphics` 画的色块占位图，全部换成**有细节的像素美术资源**，
> 精细度对标 PC 版《曹操传》（1990 年代 DOS 主机战棋）。
>
> 状态：✅ 完成（84 张资源，全量回归通过）

---

## 1. 为什么需要这一层

M3~M13 期间，所有可视元素都是 `Graphics` 画的纯色几何块：

| 元素 | 旧占位图 |
|---|---|
| 地图地形 | 40×40 纯色矩形（平原绿 / 森林深绿 / 山地灰 / 水域蓝 / 道路黄） |
| 战场地面 | 11×9 棋盘格深浅矩形 |
| 兵牌 | 阵营色圆盘 + 兵种首字 |
| 城镇 | 白框色块方块 + 城市名 |
| 资源 | 26×26 色块 + 资源首字 |
| 英雄 | 阵营色圆 + 名字首字 |

玩法完全跑得通，但**没有游戏感**。M14 解决的就是"看起来像个游戏"。

## 2. 双轨美术管线

M14 采用**双轨制**，两条轨道各司其职：

```
┌─ 轨 A：AI 生成 + 图像处理流水线 ─────────────────────────┐
│                                                          │
│  ImageGen 生成 2×2 / 3×3 / 4×4 图集                        │
│        ↓                                                  │
│  scripts/art/process-sprites.mjs                          │
│  （headless Chrome + Canvas，零图像处理依赖）               │
│        ↓                                                  │
│  抠背景 → 去光晕 → 连通域标记 → 按格归属分配               │
│  → 盒式降采样 → alpha 二值化 → 调色板量化 → 补描边           │
│        ↓                                                  │
│  public/assets/pixel/*.png（84 张）                        │
└──────────────────────────────────────────────────────────┘

┌─ 轨 B：代码程序化绘制 ────────────────────────────────────┐
│                                                          │
│  scripts/lib/pixbuf.mjs（像素画布）                        │
│  scripts/lib/pixel-art.mjs（图形定义）                     │
│  scripts/lib/png.mjs（零依赖 PNG 编码器，zlib deflate）     │
│        ↓                                                  │
│  scripts/gen-pixel-art.mjs                                │
│        ↓                                                  │
│  public/assets/pixel/base_shu.png / base_wei.png          │
└──────────────────────────────────────────────────────────┘
```

**为什么分开**：AI 画不了"规整的纯色椭圆底座"（会画出奇怪的东西），而代码画不了"有细节的人物"。
阵营底座用代码画（轨 B），其余全部用 AI 生成 + 处理（轨 A）。

### 2.1 轨 A 的处理流水线（`scripts/art/process-sprites.mjs`）

AI 生成的"像素画"有四个硬伤，直接贴进游戏是不行的：

1. 背景不是透明的（米白噪点底 + 右下角水印）
2. 源分辨率很高（角色 230~450px），要缩到 48/64px
3. 缩放后边缘糊、颜色太多，不像手绘像素画
4. **精灵可能跨格溢出**（长柄武器伸到隔壁格），按格切会把它切成两半

处理链（跑在 headless Chrome 的 Canvas 里）：

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| ① `removeBackground` | 从画布边界 flood fill，删掉「浅色低饱和且与边缘连通」的像素 | 抠掉米白底 + 水印 |
| ② `defringe` | 删掉紧贴透明区、颜色接近背景的边缘像素 | 去光晕 |
| ③ `labelBlobs` | 连通域标记，每个精灵是一个独立色块 | 为跨格归属做准备 |
| ④ 水印过滤 | 丢弃右下角区域里的小色块 | AI 工具水印 |
| ⑤ **byCell 分配** | 每个色块归给「像素占比最高」的格子 | **解决跨格切断**：溢出的部分仍属于原精灵 |
| ⑥ `cropBlobs` / `cropRegion` | 取该格所有色块的并集包围盒 | — |
| ⑦ `boxDownscale` | 盒式降采样（area average），**不是双线性** | 缩 5 倍也不糊 |
| ⑧ `binarizeAlpha` | alpha ≥128 → 255，否则 0 | 硬边，像手绘像素画 |
| ⑨ `quantize` | 颜色量化（levels 位/通道） | 限制调色板 |
| ⑩ `outline` | 补 1px 深色描边 | 统一风格，贴图叠一起不糊成一片 |

### 2.2 地形类资源：两个特殊模式

地形是**整格铺满**的，不需要抠背景，于是加了两个模式：

- **`fullCell: true`** —— 整格铺满，不抠背景、不裁切
- **`inset: 3`** —— 切掉 AI 画在格子边缘的深色边框，再铺满整格
- **`cell.crop: {size, x, y}`** —— 只取格子里的一小块再缩放

> `crop` 的必要性：森林源图一格里只有约 4 棵树，整格缩到 40px 就变成了"一排排竖条"。
> 裁出 30% 的树丛区域再缩，树冠与树干层次就回来了。

### 2.3 图集布局必须**逐格核对**

AI 生成的 4×4 图集，行序**不等于**直觉顺序。踩过的坑：

| 我以为 | 实际 |
|---|---|
| 第 0 行=平原，第 1 行=森林，第 2 行=山地，第 3 行=水域 | 第 0 行=草地，**第 1 行=成排针叶树**，第 2 行=水面，第 3 行=碎石滩 |

当时按错误映射铺图，整片草地渲染成了深绿竖条纹。
**教训**：AI 图集必须逐格导出核对（`/tmp/diag` 诊断任务导出 16 格逐一确认），不能凭直觉排。

当前各图集的真实布局：

| 图集 | 源文件 | 布局 |
|---|---|---|
| 兵种 ×4 | `A_2x2_grid_sprite_sheet_of_fou_*` | g0~g3 = 4 个兵种 |
| 英雄 ×2 | `A_2x2_grid_of_four_Chinese_Thr_*` | g0~g3 = 4 位英雄 |
| 地形 4×4 | `A_4x4_grid_of_sixteen_square_t_*` | 草 / 树 / 水 / 碎石（g15 带水印弃用） |
| 地形 3×3 | `A_3x3_grid_of_nine_square_top__*` | 草地 / 松林 / 雪山 / 海滩 / 土路 / 旱地 / 村庄 / 沼泽 / 山道 |
| 森林 2×2 | `A_2x2_grid_of_four_square_top__*` | 4 格全是密排针叶树（g3 右下带水印） |
| 建筑 2×2 | `A_2x2_grid_sprite_sheet_of_fou_2026-11-19T12-12-02` | 红城 / 蓝城 / 村庄 / 塔楼 |
| 资源 4×4 | `A_4x4_grid_sprite_sheet_of_res_*` | 金 / 木 / 矿 / 瓶 / 硫 / 晶 / 宝石 / 粮 |

### 2.4 资源清单是唯一真相来源

`src/core/pixelArt.assets.js` 是**纯数据**文件：

- 运行期（`src/core/pixelArt.js`）按它加载纹理
- 生成期（`scripts/art/process-sprites.mjs`）按同一套命名产出 PNG

> ⚠️ 该文件**不能 import phaser** —— 生成脚本要在 Node 里 import 它。

## 3. 运行时接入

### 3.1 加载（`src/core/pixelArt.js`）

```js
export function loadPixelArt(scene) {
  for (const [key, def] of Object.entries(PIXEL_ASSETS)) {
    if (scene.textures.exists(key)) continue;
    scene.load.image(key, PIXEL_DIR + def.file);
  }
  scene.load.on('loaderror', (file) =>
    console.warn('[pixelArt] 资源加载失败：', file && file.key, file && file.src));
}
```

在 `BootScene.preload()` 里调用。

### 3.2 绘制

```js
export function pixelSprite(scene, key, x, y, size, originX = 0.5, originY = 0.5) {
  if (!hasArt(scene, key)) return null;
  const tex = scene.textures.get(key);
  if (tex) tex.setFilter(Phaser.Textures.FilterMode.NEAREST);
  const img = scene.add.image(x, y, key).setOrigin(originX, originY);
  img.setDisplaySize(size, size);
  return img;
}
```

> ⚠️ **`setFilter` 在 `Texture` 上，不在 GameObject 上**
> —— Phaser 3.90 的 `Image.setFilter` 不存在，写在 GameObject 上会报
> `img.setFilter is not a function`。必须 `scene.textures.get(key).setFilter(...)`。

### 3.3 地形变体（避免重复感）

每种地形 4 个变体，按坐标散列取值：

```js
const h = ((x * 73856093) ^ (y * 19349663)) >>> 0;
variant = h % 4;
```

### 3.4 图层顺序（**踩过的大坑**）

> ⚠️ **Phaser 按插入顺序渲染**，顶层元素排在所有 layer 容器**之后**。

`pixelSprite` 默认 `scene.add.image()` → 加到 **scene 顶层**。如果瓦片这样加，
它会排在 `markLayer` / `unitLayer` 之后，把**整个战场（兵牌、高亮、格线）全盖住**。
症状是"战场一片草地，一个兵都看不见"。

修复：所有瓦片必须收进各自的 layer 容器。

**MapScene**（自底向上）：

```
groundLayer  地形瓦片（540 张）
rangeLayer   可达范围高亮
pathLayer    移动路径
resLayer     资源图标
townLayer    城镇
heroLayer    英雄头像
```

**BattleScene**：

```
gridLayer    地面瓦片（11×9=99 张）+ 棋盘明暗 + 格线
markLayer    射程 / 可移动格 / 目标环
unitLayer    兵牌
fxLayer      飘字特效（depth 800）
hudLayer     顶栏 + 操作栏
logLayer     战报
```

### 3.5 战场地面要保留棋盘感

纯铺瓦片会让 11×9 变成一整块草地，**看不出格子在哪** —— 而战棋里格子边界是刚需
（要指认移动范围、射程、站位）。所以瓦片之上叠一层：

```js
g.fillStyle((x + y) % 2 === 0 ? 0xffffff : 0x000000, 0.055);  // 交替明暗
g.fillRect(px, py, CELL, CELL);
g.lineStyle(1, 0x1b2416, 0.5);                                // 细格线
g.strokeRect(px + 0.5, py + 0.5, CELL - 1, CELL - 1);
```

### 3.6 兵牌造型：底座 + 立绘

《英雄无敌4》的"军团棋子"造型 = **阵营色底座** + **兵种立绘**站在上面。

```js
const base = pixelSprite(scene, baseKey(faction), 0, 8, 64);   // 底座 64px（正好一格）
const icon = pixelSprite(scene, unitKey(stack.unitId), 0, -6, 48);  // 立绘 48px
```

> ⚠️ **底座必须比立绘大、且立绘上移**。
> 早期版本底座 48px 与立绘同尺寸同位置 → 底座被**完全盖住**，敌我分不清。
> 现在底座 64px 中心偏下（cy=40），立绘下缘落在底座上沿，层次才对。

阵营底座由代码绘制（轨 B，`buildUnitBase`），64×64，椭圆 + 深色描边 + 底部暗面 + 顶面高光。

### 3.7 降级回退

所有像素资源加载失败时，各场景自动退回原 `Graphics` 色块：

- `hasArt(scene, key)` → `scene.textures.exists(key)`
- 地图：地形 → 纯色矩形；城镇 → 白框方块；资源 → 色块 + 首字；英雄 → 色圆 + 首字
- 战场：兵牌 → 阵营色圆盘 + 兵种首字
- UI 组件：兵牌 → 纯色圆 + 首字

`view.disc` 在有立绘时为 `null`（回退专用），`view.factionColor` 始终有值。

## 6. 验收标准

`scripts/verify-m14-ui.mjs` —— **24 项断言**，分 6 组：

| 组 | 内容 |
|---|---|
| A | 资源清单 ↔ 磁盘文件一一对应（无缺失、无冗余）；地形变体齐全 |
| B | 所有 `px_` 贴图运行时加载成功（84 张） |
| C | 地图每格都有地形瓦片（540 格）；5 种地形都用上；资源/城镇/英雄都用像素图；瓦片收在 `groundLayer` |
| D | 战场每个兵牌都有立绘 + 底座；不用色块圆盘；底座比立绘大且更低；阵营分两色且按 `playerId`；地面瓦片铺满 11×9 |
| E | 资源缺失时退化为 Graphics 色块圆盘，且仍按阵营着色 |
| F | 无资源 404、无运行时异常 |

## 7. 已知限制 / 后续

- **AI 图集有水印**：右下角水印靠 flood fill + 角落色块过滤去除；
  带水印的格子（如 4×4 的 g15）直接弃用。
- **地形变体偏少**：平原 4 变体在大地图上仍能看出重复，
  后续可让 AI 再出一批同风格草地。
- **没有动画**：兵种立绘是静态帧，战斗移动靠 tween 平移整个兵牌。
  下一步可做 2 帧走路循环。
- **水战 / 城池 UI 未覆盖**：目前只有陆地战场与野战城池。
- **美术风格未统一到完全一致**：AI 每次生成的调色板有细微差异
  （已用 `quantize` 压到 5~6 级缓解）。
