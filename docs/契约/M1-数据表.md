# M1 · 数据表（units / spells / skills / buildings / factions）

> 类型：纯数据任务，不写代码。交付 `src/data/` 下 5 个 JSON 文件的**完整版**（替换 M0 占位版）。

## 目标

把英雄无敌4的生命/守序两阵营内容，换名为三国主题，填满数据表。数值参照英雄无敌4同级兵种的相对强度，允许简化。

## 交付文件与格式

### 1. `src/data/units.json` —— 兵种表（每阵营 8 个，T1~T4 每级 2 个）

```json
{
  "id": "shu_militia",          // 唯一id：阵营_英文名
  "name": "乡勇",               // 中文名
  "faction": "shu",             // shu | wei
  "tier": 1,                    // 1~4
  "attack": 2, "defense": 2,    // 攻防
  "damageMin": 1, "damageMax": 3,
  "hp": 6,                      // 单个兵生命
  "speed": 3,                   // 决定出手顺序
  "moveRange": 4,               // 战场每回合移动格数
  "range": 1,                   // 射程（近战=1，远程 6~8；超射程攻击减半）
  "growth": 20,                 // 每周产量
  "cost": { "gold": 40 },       // 招募单价（可用7种资源任意组合）
  "abilities": [],              // 特性，见下表
  "aiValue": 40                 // AI 估值（约等于单兵综合战力）
}
```

**abilities 可选值**（战斗模块只实现这些，不要发明新的）：

| 值 | 含义 |
|---|---|
| `ranged` | 远程（可攻击范围是全场；射程内满伤、超射程减半；被近身时自身反击减半） |
| `noRetaliation` | 攻击不受反击 |
| `fly` | 飞行（无视障碍移动） |
| `twoAttack` | 每回合攻击两次 |
| `large` | 占2格（本期不用，别加） |

**兵种命名要求**（三国化，可参考下表调整）：

| 级别 | 蜀汉（生命） | 曹魏（守序） |
|---|---|---|
| T1 | 乡勇 / 弓手 | 青州兵 / 魏弓手 |
| T2 | 白毦兵 / 诸葛连弩(ranged,twoAttack) | 武卫营 / 霹雳车(ranged) |
| T3 | 无当飞军(fly) / 方士(ranged) | 虎豹骑 / 谋士(ranged) |
| T4 | 五虎上将(noRetaliation) | 虎卫统领(twoAttack) |

### 2. `src/data/spells.json` —— 魔法表（每阵营 6 个：1级3个、2级2个、3级1个）

```json
{
  "id": "heal", "name": "治疗", "faction": "shu",
  "level": 1,                    // 1~3
  "manaCost": 4,
  "target": "ally",              // ally | enemy | allAllies | allEnemies
  "effect": { "type": "heal", "base": 10, "perLevel": 5 },
  "desc": "恢复友军生命"
}
```

**effect.type 只允许以下值**（M9 魔法模块按此实现）：

| type | 参数 | 含义 |
|---|---|---|
| `heal` | base, perLevel | 治疗友军 |
| `damage` | base, perLevel | 伤害敌军 |
| `buff` | stat, value, turns | 增益（stat: attack/defense/speed/damageMax） |
| `debuff` | stat, value, turns | 减益（value 为负数） |
| `resurrect` | base | 复活友军（回复生命可超上限复活死人） |

**字段约束（M9 定案，`scripts/check-data.mjs` 已纳入校验）**：

| 字段 | 约束 |
|---|---|
| `id` | 全表唯一 |
| `name` | 非空中文名 |
| `faction` | `shu` / `wei` |
| `level` | 1~3 的整数 |
| `manaCost` | 正整数 |
| `target` | `ally` / `enemy` / `allAllies` / `allEnemies` |
| `desc` | 非空效果说明 |
| `effect.base` | `heal`/`damage`/`resurrect` 必填，正整数 |
| `effect.perLevel` | `heal`/`damage` 可选，非负整数 |
| `effect.stat` | `buff`/`debuff` 必填，取值 `attack`/`defense`/`speed`/`damageMax`/`damageMin`/`canAct` |
| `effect.value` | `buff`/`debuff` 必填，整数；`buff` 为正、`debuff` 为负 |
| `effect.turns` | `buff`/`debuff` 必填，≥1 的整数 |

⚠️ **致盲（`zhimang`）是 `debuff` 的唯一例外**：它的 `stat` 是 `canAct`、`value` 是 `0`，
表示"不能行动"而不是数值减益。判定被致盲要用 `isBlinded(stack)`，
**不要**用 `buffModifier(stack, 'canAct')`——`canAct` 不是可加总的数值属性。

蜀汉（仁德系）：治疗、祝福、护体、驱邪、复活、天佑。
曹魏（奇策系）：迟缓、运筹、致盲、火计、伏兵、空城。

### 3. `src/data/skills.json` —— 技能表（共 8 个，每技能 maxLevel 3）

```json
{ "id": "leadership", "name": "统帅", "maxLevel": 3,
  "effect": { "type": "armyAttack", "perLevel": 1 }, "desc": "每级全军攻击+1" }
```

effect.type 允许值：`armyAttack` `armyDefense` `movePoints` `mana` `goldPerDay` `rangedDamage` `meleeDamage` `healBonus`。
技能池：统帅、行军、谋略、理财、弓术、武勇、医疗、防御。

### 4. `src/data/buildings.json` —— 建筑表（每阵营 8 个建筑 + 通用建筑）

```json
{ "id": "shu_barracks2", "name": "白毦营", "faction": "shu",
  "cost": { "gold": 1500, "wood": 10 }, "income": {},
  "requires": ["shu_barracks1"], "recruitTier": 2, "recruitUnit": "shu_bai'er",
  "desc": "可招募白毦兵" }
```

规则：大本营(产金500/日)→内政厅(产金1000/日，费5000金)；T1~T4 每级 2 个招募建筑（同级的两个二选一，互斥用 `excludes` 字段标注）；铁匠铺、市场、酒馆为通用建筑。

### 5. `src/data/factions.json` —— 阵营表

沿用 M0 占位结构，补充 `heroPool`（每阵营 4 个可招募英雄名，三国人物）。

## 约束

- 只交付 JSON 文件，不写任何 JS。
- JSON 必须合法（无注释、无尾逗号）。
- 数值平衡参考：相邻 Tier 单兵 aiValue 约 2~3 倍递增；同 Tier 两兵种 aiValue 接近。
- 全部中文命名。

## 验收标准

1. `node -e "JSON.parse(require('fs').readFileSync('src/data/units.json'))"` 五个文件全部解析成功。
2. units.json 恰好 16 个兵种，每阵营 T1~T4 各 2 个。
3. spells.json 恰好 12 个魔法，effect.type 都在允许值内。
4. buildings.json 中每个 recruitTier≥1 的建筑都有对应存在的 recruitUnit。
