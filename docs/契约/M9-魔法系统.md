## 目标

实现战场施法。魔法效果全部数据驱动（spells.json 的 effect 字段），本模块是"效果解释器"。

## 实际交付的接口

## 规则细节（定案）

- **魔法定义以静态表为唯一权威源**：本模块 `import spells.json`（`with { type: 'json' }`）。
  原因：契约冻结了 `canCast(state, heroId, spellId)` 的签名（不带 `data` 参数），
  而施法需要 `manaCost` / `target` / `effect`。若 `canCast` 读运行时 data、
  `castSpell` 读静态表，两边不一致会出现"能列出但施不了"的错位。
  `data` 参数只为契约签名保留。
- **法力消耗** = spells.json 的 `manaCost`，从 `hero.mana` 扣。
- **每方每场战斗每轮限施法 1 次**：记在 `battle.spellCastThisTurn = { attacker, defender }`，
  由 M6 的 `nextTurn` 在新一轮开始时重置。超限返回 `reason: 'spellLimitReached'`。
- **施法不推进回合、不消耗 stack 的行动、不触发反击**：施法是"英雄动作"，
  与 stack 的出手是两条独立的线。
- **目标类型** `target`：`ally`（单个友军）/ `enemy`（单个敌军）/
  `allAllies`（全体友军）/ `allEnemies`（全体敌军）。
  阵营不匹配返回 `wrongSide`，目标不存在返回 `noTarget`。
- **buff/debuff** 压入 `stack.buffs`，格式 `{ spellId, stat, value, turnsLeft }`。
  同属性重复施加时**替换**（取绝对值更大的）而不是叠加，避免数值失控。
- **致盲**（`debuff` 且 `stat:'canAct'`、`value:0`）：被致盲的 stack 本轮不能行动。
  判定用 `isBlinded(stack)`，**不要**用 `buffModifier(stack,'canAct')`——
  `canAct` 不是可加总的数值属性。
- **治疗量** = `(base + perLevel × 英雄等级) × (1 + 医疗技能加成/100)`。
  治疗优先给还活着的兵补血（`stack.hp` 补到 `maxHp`），
  溢出部分用于复活阵亡的兵（`count` 增加，最多到 `stack.initialCount`）。
- **伤害魔法** = `base + perLevel × 英雄等级`，走 M6 的 `applyDamage`，**不触发反击**。

## effect.type 处理矩阵

| type | 行为 | 数据表字段 |
|---|---|---|
| `heal` | 回复生命，溢出部分复活 | `base`, `perLevel` |
| `resurrect` | 同 heal（数据层面是固定回复量） | `base` |
| `damage` | 造成伤害，走击杀计算 | `base`, `perLevel` |
| `buff` | 压入增益 buff | `stat`, `value`, `turns` |
| `debuff` | 压入减益 buff | `stat`, `value`, `turns` |

未知 `effect.type` 返回 `{ ok:false, reason:'unknownEffect' }`。

## 对 M6 的接入点

### 1. 新增 `src/logic/stackOps.js`（打断循环依赖）

`battleLogic` 需要 `applyDamage` / `buildTurnQueue`，`magicLogic` 需要 `buffModifier` / `tickBuffs`，
两边互相 import 会形成 ESM 循环依赖。因此把"谁都需要、且不依赖任何其他逻辑模块"的
原子操作抽到 `stackOps.js`：

```
battleLogic ──▶ stackOps ◀── magicLogic
```

`stackOps.js` 导出：`pushLog`、`applyDamage`、`buffModifier`、`stackStat`、
`stackSpeed`、`isBlinded`、`buildTurnQueue`。

`battleLogic.js` 用 `export { ... }` 把这些原样转出，保持既有导入路径不变，
`battleLogic.test.js` 无需修改。

### 2. `battle.stacks[].buffs`

每个 stack 新增 `buffs: []` 字段，元素为 `{ spellId, stat, value, turnsLeft }`。

### 3. `battle.spellCastThisTurn`

`initBattle` 新增 `{ attacker: false, defender: false }`，
`nextTurn` 在新一轮开始时重置。

### 4. 致盲的落地方式

被致盲的 stack 有两条路径被"消费"（标记 `acted=true` + 写战报「X 被致盲，无法行动」）：

| 场景 | 处理位置 |
|---|---|
| 指针正好停在它身上 | `nextTurn` 第 1 步 |
| 指针推进时路过它 | `advanceToActionable`（`battleLogic` 内部函数） |

并且 `moveStack` / `attackStack` 都会拒绝被致盲的单位（`reason: 'blinded'`），
保证"本轮不能行动"在逻辑层是硬约束而不只是界面表现。

### 5. `buildTurnQueue` 的指针保持

速度 buff 改变出手顺序时会重建 `turnQueue`，而 `battle.currentTurn` 是**下标**。
`buildTurnQueue` 现在会记住"当前正在行动的是哪个 stack"，重建后把它的下标找回来，
避免施法改变速度导致当前行动单位被偷换。

## 界面与 AI 接入（M9 附带交付）

### 施法面板 `src/scenes/ui/spellPanel.js`

```js
openSpellPanel(scene, {
  state, battle, heroId,
  onPick: (spellId, def) => void,   // 玩家选了某个魔法
  onCancel: () => void              // 玩家点了关闭
})
```

面板（depth 950 的弹层）列出英雄已习得的每个魔法，每张卡显示：

| 元素 | 内容 |
|---|---|
| 名称 | `def.name`（法力不足时置灰 `#5d6d80`） |
| 法力消耗与目标类型 | `法力 N　单个友军 / 单个敌军 / 全体友军 / 全体敌军` |
| 描述 | `def.desc` |
| 目标标记 | 群体魔法标「群体（无需选目标）」，单体标「单体（需选目标）」 |

可用条件 = `!alreadyCast && canCast(state, heroId, def.id).ok`；
不可用的卡**不注册交互**（点不动），面板底部提示对应原因
（「法力不足，无法施放任何魔法」/「本轮已施法过，下一轮才能再次施法」）。

**网格布局**：魔法数随英雄等级增长（蜀汉 1~3 级共 6 个魔法），横向一排排不下，
所以每行最多 3 张，面板宽高按实际行列数算出来（`computeLayout`）。
面板右上角固定一个「[关闭]」按钮，**点遮罩也能关**——反悔不施法时必须能退出。

### BattleScene 的施法流程

```
[施法] 按钮 → openSpellPanel() → 点魔法卡
   ├─ target 为 allAllies / allEnemies → 直接施放（不进选目标模式）
   └─ target 为 ally / enemy         → startCasting() 进「选目标」模式
                                          ├─ spellTargets() 算出合法目标
                                          ├─ 战场画紫环（0x9b59b6）高亮
                                          └─ 点合法目标 → castOnTarget() 施法
                                             点别处 → cancelCasting()
```

要点：

- **施法是英雄动作，不推进回合**：不消耗 stack 的 `acted`，不触发反击，
  因此施法后 `currentTurn` 不变，当前行动单位仍在玩家手上。
- 施法按钮在「本轮已施法过」时变灰（`hasCastThisTurn`），并在进入选目标模式时
  变成「[取消施法]」。
- 选目标模式优先于其它交互：`handleClickCell` 开头就分支处理，
  所以点战场任意位置都能退出施法模式而不会误触移动/攻击。

### 电脑方施法 `battleAI.aiCastSpell(state, data, heroId)`

每轮至多施法一次（由 `battle.spellCastThisTurn` 控制），策略优先级：

1. **伤害魔法打残血敌人** —— 优先收割血量百分比最低的敌人
2. **减益魔法** —— 致盲（`stat:'canAct'`）优先（敌人整轮不能动），其次按减益强度绝对值
3. **治疗自己人** —— 己方有伤员（`hp < maxHp` 或已减员）时才用
4. **增益自己人** —— 己方全员满血时才用

`BattleScene.scheduleAI()` 在驱动电脑单位出手**之前**调用 `aiCast()`，
所以电脑的施法与出手也是两条独立的线。
