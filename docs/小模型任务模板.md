# 小模型任务投喂模板（混元4flash 等轻量模型专用）

> 用法：每实现一个模块，把下面模板填好后**一次性**发给小模型。一次只喂一个模块。

---

## 模板（复制以下内容，替换 `【】` 部分）

```
你是一个前端游戏开发工程师，为 Phaser 3 游戏《出祁山》（英雄无敌式回合制策略）实现一个模块。

【项目铁律】
1. 逻辑层文件（src/logic/）是纯 JS：禁止 import phaser，只能 import EventBus 和数据查询函数。
2. 所有游戏状态是单一纯数据对象 state（可 JSON 序列化），结构见随附的 M0 契约。
3. 修改状态后通过 EventBus 发事件（bus.emit），事件名见随附 EventBus.js 头部注释。
4. 代码注释用中文。不要发明契约之外的字段和函数。

【你的任务】实现模块 【模块编号】：【模块名】

【契约全文】
（此处完整粘贴 docs/契约/M【编号】-*.md 的内容）

【状态结构契约】
（此处完整粘贴 docs/契约/M0-状态结构.md）

【相关现有代码】
（粘贴该模块依赖的现有文件，如 EventBus.js、被依赖模块的导出函数签名清单——
 只贴导出函数的 JSDoc 和签名，不贴函数体，控制篇幅）

【数据样例】
（粘贴 src/data/ 下本模块要用的 JSON 文件的 2~3 条示例记录）

【输出要求】
1. 直接输出完整可运行的文件内容，用 ```js 代码块包裹，文件路径写在代码块上方注释里。
2. 需要附带测试的模块，一并输出测试文件。
3. 不要解释思路，不要输出契约之外的额外文件。
```

---

## 投喂顺序与搭配清单

| 顺序 | 模块 | 需随附的文件 |
|---|---|---|
| 1 | M1 数据表 | 只需契约 M1 + 现有占位 JSON |
| 2 | M2 地图逻辑 | 契约 M0/M2 + EventBus.js + map_default.json |
| 3 | M4 资源与回合 | 契约 M0/M4 + GameState.js |
| 4 | M3 地图渲染 | 契约 M3 + M2 导出签名 + 现有 MapScene.js |
| 5 | M5 城建与招募 | 契约 M5 + M4 导出签名 + buildings/units 样例 |
| 6 | M6a→M6b→M6c 战场逻辑 | 契约 M6 + units.json 全文 |
| 7 | M8 技能系统 | 契约 M8 + skills.json |
| 8 | M9 魔法系统 | 契约 M9 + spells.json + M6 相关签名 |
| 9 | M7 战场渲染 | 契约 M7 + M6/M9 导出签名 |
| 10 | M10 战斗 AI | 契约 M10 + M6 导出签名 |
| 11 | M11 地图 AI | 契约 M11 + M2/M4/M5 导出签名 |
| 12 | M12 存档 | 契约 M12 + GameState.js |
| 13 | M13 UI 组件 | 契约 M13（独立，可提前） |

## 验收流程（每个模块交付后）

1. 把代码存到对应路径；
2. 逻辑层模块跑契约里的 `node` 验收命令或测试文件；
3. 场景模块起 `npm run dev`，用无头浏览器打开检查控制台无报错、核心交互可用；
4. 不通过：把**报错原文**贴回给小模型让它修（别自己描述问题，直接贴报错）；
5. 连续 3 次修不对：该模块拿回给我（大模型）处理。

## 常见翻车点（提前写进 prompt 可规避）

- 小模型爱发明字段：模板里已写"不要发明契约之外的字段"。
- 小模型爱 import phaser 进逻辑层：模板铁律第 1 条。
- 小模型写 ESM/CJS 混用：项目全 ESM（package.json `"type": "module"`）。
- 返回的代码带解释文字：输出要求第 3 条。
