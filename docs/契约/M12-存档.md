## 存档格式

```
key: ooqs_save_<slot>          // slot ∈ {0, 1, 2, 'auto'}

value: {
  version: 1,                  // STATE_VERSION，结构变动时 +1
  savedAt: 1730000000000,      // 时间戳（毫秒）
  label: '第1周第1天',          // 给人看的摘要
  state: { ...GameState }      // 局面快照
}
```

`state` 就是 M0 定义的 GameState 原样（`meta` / `players` / `heroes` / `towns` / `map` / `battle` / `gameOver`）。

## 实现要点（与原始契约的差异说明）

### 1. `state.battle` 存档时置空

战斗是临时场景，存档只在地图层做（玩家点「结束回合」、每天自动存档都在地图层），
因此 `saveGame` 把 `battle` 强制置 `null`，避免读档后出现「半个战场」的坏状态。

### 2. 存储后端可注入（隐私模式降级 + Node 测试）

契约写的是 localStorage，但：
- **浏览器隐私模式**下 `localStorage` 存在却 `setItem` 会抛异常 → 首次使用时做一次写探针，失败则降级到内存 Map（游戏仍可玩，只是不落盘）。
- **Node 单测**没有 localStorage → 同样落到内存 Map。

两个场景共用同一套兜底实现，`__setStorage()` 可显式注入。

### 3. 损坏检测分三层

读档时依次判定，任何一层不过都返回 `corrupted`：

| 层 | 检查 | 不通过 → |
|---|---|---|
| ① JSON 解析 | `JSON.parse` 是否抛错 | corrupted |
| ② 顶层结构 | 是对象吗 / 有 `version` 数字吗 / 有 `state` 对象吗 | corrupted |
| ③ state 基本字段 | 有 `meta` 吗 / `players`/`heroes`/`towns` 是数组吗 | corrupted |

版本号单独判：③ 过了但 `version !== STATE_VERSION` → **versionMismatch**（不做迁移）。

`listSaves()` 对损坏档位返回 `{ slot, label: '存档损坏', savedAt: 0, corrupted: true }`，
而不是静默当成空位 —— 玩家才能看到「这个档位坏了」并去删它。

### 4. 读档返回的是独立副本

`loadGame` 返回的是 `JSON.parse` 出来的对象，改它不会影响 localStorage 里的内容。
单测「读档返回的是独立副本，改它不会污染存档」守着这条。

### 5. `saveGame` 返回值比契约多

契约写 `returns { ok, reason? }`，实际成功时多返回 `{ slot, savedAt, label }`，
方便 UI 直接显示「已保存到存档位 1（第1周第1天）」。失败时只返回 `{ ok:false, reason }`。

### 6. 失败原因（reason）取值表

| reason | 触发条件 |
|---|---|
| `invalidSlot` | 档位号不在 {0,1,2,'auto'} 内 |
| `invalidState` | state 不是对象 |
| `serializeFailed` | `JSON.stringify` 抛错（如 state 含循环引用） |
| `quotaExceeded` | localStorage 配额满（按 `QuotaExceededError` 名字判定） |
| `storageError` | 其他读写异常 |
| `empty` | 该档位没有存档 |
| `corrupted` | 内容被篡改 / 结构不合法 |
| `versionMismatch` | 存档版本 ≠ 当前 STATE_VERSION |

## UI 接入

### 存档面板（`src/scenes/ui/savePanel.js`）

地图状态栏右上角 `[存档]` 按钮打开。面板 4 行（存档位 1/2/3 + 自动存档），每行显示：
- 位名 + 摘要（`第1周第1天　2026-11-19 18:53`）或「空」/「存档损坏，无法读取」
- 三个按钮：`[存档]` `[读取]` `[删除]`

规则：
- 自动位**不能手动写**（它由每天开始时自动写入），只能读取/删除。
- 只有有效存档才能点「读取」；损坏档位「读取」置灰。
- 点「读取」成功 → 回调 `onLoad(state)`，由 MapScene 换掉 state 并重建场景。
- 面板 depth 960（高于施法面板 950、事件总线层）。

### 读档后如何恢复局面

```js
// MapScene.applyLoadedState(loaded)
this.registry.set('state', loaded);       // 换掉全局状态
this.registry.remove(AI_RESUME_KEY);       // 清掉上一局的电脑回合续跑信息
this.scene.start('MapScene');              // 重建场景，让精灵/可达格缓存全部重画
```

必须重建场景：场景里的英雄精灵、显示位置缓存、可达格集合都是按开局状态建的，
换 state 后不重画就会显示上一局的画面。

### 自动存档

`bus.on('day:new')` 时调 `autoSave(state)` 写 `'auto'` 位。
`day:new` 在 `turnLogic.endTurn` 里**切回玩家 0** 时触发，即「新的一天开始」，
此时局面稳定（战斗已结算完）。

自动存档失败不打断游戏流程，只在 console 留一条 warn。

### URL 深链读档

```
http://localhost:5173/?slot=0        # 读存档位 1
http://localhost:5173/?slot=auto     # 读自动存档
```

BootScene 启动时读 URL 参数，`loadGame` 成功就用那一局开局；失败（空位/损坏/版本不符）
则照常开新局并在 console 留 warn，**不崩**。

## 已知限制

1. **不做存档迁移**（契约明确要求）。`STATE_VERSION` 一旦 +1，旧存档一律 `versionMismatch` 读不出来，只能新开局。
2. **战斗中途不能存档**。存档只在地图层开放；`state.battle` 一律置空。
3. **AI 续跑信息不存档**。M11 的「已行动过哪些英雄」存在 Phaser registry 里（跨场景保留但不是 state 的一部分），读档后清空，重新规划。
4. **隐私模式下不落盘**。降级到内存存储，刷新页面后存档丢失（console 有 warn）。
5. **单机单档**。没有云存档、没有多存档槽的元数据（存档时间/标签已含在存档内容里，但独立存储槽位元信息是 M13 可扩展项）。
