## 目标

实现回合制战棋的完整规则。战场为 **15×9 方格**，攻方从左入场、守方从右入场。

## 战场尺寸：11 × 9

**宽度从最初的 15 改成 11**（M6b 实现时修正）。

原因：双方开局分别在 x=0 和 x=14，相距 14 格；而近战兵 moveRange 只有 4，
推 3 个回合都碰不到对手，战斗根本打不起来（自动化对局测试直接死循环）。
英雄无敌4 的战场正是 11×11，改成 11 宽后近战兵 2 回合接敌、远程兵开火即可全场覆盖。

> **`cellsInRange`（M7 引入）**：切比雪夫距离 ≤ 射程的格子列表（含自身所在格），
> 受战场边界（11×9）裁剪。⚠️ 它表示的是**满伤害范围**，
> 不是「只有这些格子能被打」——按远程规则，远程单位可以攻击全场任意敌人，
> 超出射程只是伤害减半。该函数供界面画射程预览用。

### 伤害公式（computeDamage）

```
基础   = random(damageMin ~ damageMax) × count      // 单兵伤害 × 数量
修正   = 攻击 > 防御 → 1 + min(差值×5%, 3)           // 加成上限 +300%
         攻击 < 防御 → max(1 + 差值×2%, 0.3)         // 减益下限 30%
         相等       → 1
最终   = 基础 × 修正
         × 0.5（超出自身射程 outOfRange）
         × 0.5（守方处于防御姿态 defending）
       四舍五入，最小 1
```

### 远程规则（M6b 修订，权威口径）

| 项 | 规则 |
|---|---|
| 射程字段 | `units.json` 每兵种有 `range`；近战 = 1，远程 6~8 |
| 目标选择 | **可攻击范围是全场**，任意敌人都可选，不因距离而打不到 |
| 射程内 | 满攻击力 |
| 超出射程 | 该次攻击伤害减半（×0.5） |
| 被近身 | **不再封锁射击**（仍可打全场），只影响它自己的**反击**：反击伤害再减半 |
| 近战单位 | 仍然必须与目标八方向相邻才能攻击；射程=1，天然不会超射程 |

倍率常量集中在 `battleLogic.js` 的 `DAMAGE_MULT`：
```js
export const DAMAGE_MULT = {
  RETALIATION: 0.5,          // 反击通用半伤
  OUT_OF_RANGE: 0.5,         // 超出射程
  ENGAGED_RANGED_RETAIL: 0.5,// 远程被近身时的反击减伤
  DEFENDING: 0.5             // 守方防御姿态
};
```

**举例**：弓手（range 6）站在 (0,0)，敌人站在 (10,0)，距离 10 > 6 → 伤害减半；
敌人走到 (5,0)，距离 5 ≤ 6 → 满伤害。弓手被敌人贴到相邻时，
它打别人仍按射程算，但**它自己的反击**减半（0.5 × 0.5 = 1/4）。

### 关键语义（M6b 定案，后续 M7/M10 必须遵守）

1. **移动不结束回合**：`moveStack` 只设 `moved=true`，攻击完才由调用方调 `nextTurn`。
2. **远程可全场攻击**：`ranged` 兵种的目标列表 = 全部敌人；射程只影响伤害倍率，不影响能否选目标。
3. **射程衰减**：`isOutOfRange(attacker, defender)` = `cellDistance > stackRange(attacker)`。
4. **近战必须相邻**：无 `ranged` 特性的单位只能打八方向相邻的敌人。
5. **攻击次数**：`twoAttack` 特性一回合打两次（每次独立结算伤害）。
6. **反击（还击）条件**（全部满足才反击）：
   - 守方还活着、且本轮未反击过（`retaliated` 为 false）
   - 守方不在防御姿态（防御时不反击）
   - 攻方没有 `noRetaliation`
   - **近战守方必须与攻方相邻**（隔空近战不合理）；远程守方可远距离反击
7. **反击伤害** = 守方按同一公式算出的伤害 × 0.5；
   远程守方**被近身**时再 × 0.5（即 1/4）。
8. **一轮结束**重置 `acted / moved / defending / retaliated` 四个标记。


**为什么把数值拷进 stack**：战斗过程中不必反复查 units.json，M9 的 buff、M10 的 AI 都直接读 stack；
所有数值仍来自 units.json，没有写死。

### 关键语义

1. **布阵**：主列（攻方 x=0 / 守方 x=10），按 9 行均布；超过 9 个 stack 才溢出到次列（x=1 / x=9）。
   例：7 个 stack 的 y = [0,1,3,4,5,7,8]。
2. **出手排序**：速度降序；速度相同则**攻方先**；同方同速保持原有顺序。
   ⚠️ 重建队列后 `battle.currentTurn`（下标）必须跟着还原到同一个 stack，
   否则速度 buff 会偷换"当前行动单位"。
3. **一轮结束**（队列走完）：round+1 → 重置 acted/moved/defending/retaliated → buff 的 turnsLeft-1（归零移除）→ 重新排序队列。
4. **胜负判定**：一方 stack 全灭即分胜负；双方全灭判 **'draw'**（契约原文为 null，实现扩展为 'draw' 便于界面处理）。
5. **伤害施加**：队首兵逐个吸收伤害，hp 归零则该兵阵亡、下一个兵满血补位。
   满血时与契约的 `floor(伤害/单兵hp)` + 余数扣队首 完全等价；队首兵受伤过时更准确。
   全灭后剩余伤害无处施加（作废），但会作为 `remaining` 返回。
6. **战报**：`battle.log` 存 `{ text }` 数组。

| 场景 | 处理位置 |
|---|---|
| 指针正好停在它身上 | `nextTurn` 第 1 步 |
| 指针推进时路过它 | `advanceToActionable`（内部函数） |

**模块分层**：M9 引入了 `src/logic/stackOps.js`，把双方都需要的底层原子操作抽出来，

```
battleLogic ──▶ stackOps ◀── magicLogic
```

`battleLogic.js` 用 `export { ... }` 把 `applyDamage` / `stackStat` / `stackSpeed` /
`buffModifier` / `isBlinded` / `buildTurnQueue` / `pushLog` 原样转出，
既有导入路径不变，`battleLogic.test.js` 无需修改。

### M6a 期间修掉的地图逻辑 bug（影响遭遇战）

`mapLogic.checkTileInteraction` 原来用 `heroes.find(...)` 取该格英雄，
**进攻方踩上敌方英雄的格子后，同格有两个英雄，find 先找到的是自己**，
于是走"自己站在自己格上不算交互"分支返回 null —— **遭遇战永远不触发**。
已改为 `find(h => h.pos.x===pos.x && h.pos.y===pos.y && h.playerId !== me.id)`，并加了回归测试。

### `battle.armies` —— 开战时的军队快照

`initBattle` 现在会记录 `battle.armies = { attacker: [{unitId,count}], defender: [...] }`，
用于算"被击败军队总价值"。经验按**开战时的编队**计算（不是残余兵力），
因为败方整支军队都会损失。

### 结算规则（M6c 定案，后续模块必须遵守）

1. **战后治疗**：所有幸存 stack 的队首兵回满血（`hp = maxHp`）。
2. **胜方写回**：胜方英雄的 `army` = 幸存军队（同 unitId 合并）。
3. **败方移除**：败方英雄从 `state.heroes` 移除（战败被俘），其军队全部损失。
   平局则双方都移除。可用 `opts.removeLoserHero = false` 切换成"撤退保留"。
4. **攻城战**：
   - 攻方获胜 → 城镇 `playerId`/`faction` 改判为攻方，守军清空，**建筑保留**；
   - 攻方战败 → 城镇归属不变，幸存守军写回 `town.garrison`。
5. **经验**：胜方英雄获得 `floor(败方军队总价值 / 10)` 点经验，可连升多级。
   攻城战由攻方英雄拿守军价值的经验；守方（城镇）获胜时没有英雄，无人拿经验。
6. **防死锁补将**：某玩家因战败失去最后一个英雄、但还有城镇时，
   自动在**自己的城镇**补一名新武将（`townLogic.hireHero`）：
   - 名字取自 `factions.json` 的 `heroPool`，跳过已在场的和刚被俘的；
   - 站在城镇格上（玩家点城镇就能进城）、没有军队、需要自己招募；
   - 阵营初始魔法沿用 `startSpells`。
7. **收尾**：`state.battle = null` → 发 `battle:resolved` → 调 `checkGameOver`，
   若全局分出胜负再发 `game:over`。

### M8 技能加成接入战场（M8 定案，M6 后续模块必须遵守）

技能加成在**布阵时**一次性烘进 stack，战斗过程中不再变化：

| 技能效果 | 接入方式 | 位置 |
|---|---|---|
| 统帅 `armyAttack` | `stack.attack = unit.attack + 加成` | `initBattle` → `buildSide` |
| 防御 `armyDefense` | `stack.defense = unit.defense + 加成` | `initBattle` → `buildSide` |
| 弓术 `rangedDamage` | `stack.damagePct = 加成`（仅 ranged 特性 stack） | `initBattle` → `buildSide` |
| 武勇 `meleeDamage` | `stack.damagePct = 加成`（仅近战 stack） | `initBattle` → `buildSide` |

伤害百分比在 `computeDamage` 里生效：

```
总伤害 = 随机(damageMin~damageMax) × count
       × 攻防差修正
       × (1 + stack.damagePct / 100)     ← M8 技能加成
       × 0.5（超出射程）
       × 0.5（守方防御姿态）
```

**取英雄加成的方式**：`skillBonus(state, heroId, effectType)`，
由英雄 id 查 `hero.skills` 各技能等级 × `perLevel` 求和。
攻城战守方是城镇（无英雄）→ 守方无技能加成。

### 电脑方英雄自动加点（M8）

`resolveBattle` 给**电脑方**英雄发经验后，会自动调用 `autoChooseSkill`
把 `pendingLevels` 消耗掉（按效果类型权重挑选），避免 AI 的技能点堆积浪费。
玩家方英雄不自动加点，交给界面（BattleScene 结算面板 / TownScene / MapScene 状态栏）。
